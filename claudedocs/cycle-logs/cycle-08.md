## Scope & Implementation

**STEP 1 — 설계 판단 하나.** 진입점을 만들면 "무엇을 검사하는가"가 CI 와 로컬 두 곳에 적히게 되고, 그건 cycle-07 이 방금 고친 것과 정확히 같은 종류의 드리프트다. ⇒ **한쪽이 다른 쪽을 부르게** 한다: 목록은 `check-all.py` 만 갖고, CI 는 그것을 부르는 스텝 하나가 된다.

한 걸음 더: 목록을 `check-all.py` 안에 **나열하지도 않는다.** 계약 검사를 먼저 돌리고, 그 옆의 `test-*.py` 를 정렬해 **발견**한다. 테스트 파일을 추가하면 그것만으로 편입된다 — 등록을 잊어 검사가 조용히 빠지는 경로 자체가 없어진다.

- `scripts/ci/check-all.py` 신설 — 발견한 검사를 순서대로 실행하고, **하나가 실패해도 나머지를 끝까지 돌린 뒤** 어떤 것이 실패했는지 이름으로 요약한다(첫 실패에서 멈추면 한 번에 한 개씩밖에 못 고친다).
- `.github/workflows/ci.yml` — 스텝 3개를 1개로. 왜 목록이 여기 없는지를 주석으로 남겼다.
- `CONTRIBUTING.md` — 머리말에 "push 전에 이것을 돌린다" + 필요한 것(PyYAML 포함 Python, `bash`, `node`). CI 가 강제하는 규칙을 기여자가 미리 확인할 경로가 이제 존재한다.

## Verification & Defect Resolution

수용 기준을 검사 전에 고정: ① 진입점이 세 검사를 전부 돌리고 통과 ② **실패가 실제로 전파되는가**(exit 비영, 어떤 검사가 실패했는지 이름이 나오는가) ③ 실패해도 나머지가 계속 도는가 ④ CI 스텝이 실제로 하나인가.

```
실제 리포: all 3 check(s) passed   exit=0
실패 전파 확인(스크립트가 없는 임시 트리에서 실행):
  exit=1
  20 case(s), 9 failure(s)
  FAILED: test-shared-scripts.py          <- 실패한 검사를 이름으로 지목
  (계약 검사가 먼저 통과한 뒤 이 검사가 돌았으므로 첫 실패에서 멈추지 않는 것도 함께 확인됨)
ci.yml 스텝: ['Checkout', 'Run all checks'] — 검사 스텝 1개
```

결함 발견 0건.

**막다른 길 하나 기록.** 실패 전파를 확인하려고 임시 트리의 `ci.yml` 에서 `timeout-minutes` 를 제거하려 했으나, 셸과 Python 사이의 경로 변환이 어긋나 주입이 실패했다(그 사실이 출력에 그대로 드러났다). 다른 경로로 같은 것을 확인했으므로 다시 시도하지 않았다 — 계약 검사의 실패 동작 자체는 자가 테스트 19케이스가 이미 고정하고 있고, 이 사이클이 확인해야 했던 것은 **`check-all` 이 하위 검사의 실패를 삼키지 않는가**였다.
