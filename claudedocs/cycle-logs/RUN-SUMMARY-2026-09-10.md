## 2. 넘기는 결정 (L2 — 사람 몫)

Blocked-on-Human 원장: **비어 있음.** 이 런에서 자원 부족으로 막힌 스코프는 없었다. 아래는 전부 결정-급이다.

### D-a. push 여부와 시점

이 런의 모든 변경이 여기 묶여 있다. 선택지는 ⑴ 지금 push ⑵ 보류.

`push` 는 이 리포에서 CI 를 처음 돌게 만든다 — 즉 `ci.yml` 이 실제 러너에서 통과하는지가 push 로만 확인된다. 반대로 보류하면 로컬 검증까지만 확인된 상태로 남는다. **권고: push.** 잠기는 것은 — 이 리포가 앞으로 push/PR 마다 검사를 돌린다는 것, 그리고 워크플로 변경이 `@main` 을 쓰는 소비자에게 즉시 도달한다는 것이다(현재 알려진 소비자는 SHA 핀이라 해당 없음).

### D-b. 소비자 SHA 핀 전진 (ROADMAP P4)

소비 리포는 `@a812e48` 핀이라 push 만으로는 **이 런의 결과가 어디에도 도달하지 않는다.** 선택지는 ⑴ push 후 핀 전진 ⑵ 전진 보류(이 리포만 최신). 핀 전진은 세션 워크스페이스 밖 리포의 코드 변경이라 **여기서 수행할 수 없다** — 그 리포를 소유한 세션·사람이 해야 한다. **권고: push 가 끝나고 CI 그린을 확인한 뒤 전진.** 잠기는 것은 소비자가 6시간 상한 대신 20분 상한을 받는다는 것이고, 그 외 동작 변화는 없다(권한은 좁아지기만 하고, 게시 경로 자체는 그대로).

### D-c. `cleanup-expired-artifacts.yml` 을 계속 제공할 것인가

실측 결론: **용량을 회수하지 않는다.** 남는 효과는 아티팩트 목록의 레코드 정리뿐이다. 선택지 ⑴ 유지(보고는 이제 정직하다) ⑵ 제거 ⑶ 용량을 실제로 다루는 것으로 대체(업로드 쪽 `retention-days` 규약 강제 등). ⑵ 는 소비 리포 3곳이 참조 중이라 핀 전진 시 워크플로 오류가 되므로 그쪽과 조율이 필요하다. **권고: 당장은 ⑴ 유지, 다만 ⑶ 을 다음 백로그로.** 잠기는 것은 3곳이 매주 용량과 무관한 cron 을 계속 돈다는 것 — 공개 리포는 실행 분(minutes)이 무과금이라 비용 피해는 없고, 남는 것은 "정리되고 있다"는 오해뿐인데 그건 이제 요약과 문서가 막는다.

### D-d. `CHANGELOG.md` 도입 여부

소비자가 SHA 를 전진시킬지 판단할 근거가 현재 없다. 선택지 ⑴ 도입 ⑵ 도입하지 않음(릴리스 관례 없는 상태 유지). **권고: 보류.** 이 리포는 태그도 버전도 없고, 변경 빈도가 낮아 지금은 git log 로 충분하다. 잠기는 것은 소비자가 "무엇이 바뀌었나"를 커밋 목록으로 읽어야 한다는 것. 소비자가 늘거나 핀 전진이 정례화되면 그때가 도입 시점이다.

### D-e. 구조 개선 제안 3건

- **`CONTRIBUTING.md` ↔ `skills/repo-conventions/SKILL.md` 중복** — 구조 규칙 4개가 양쪽에 있다. 스킬 자신이 "중복 금지"를 규칙으로 갖고 있어 자기 규칙을 어기는 모양이다. 권장: CONTRIBUTING 을 유일 정본으로, 스킬은 요약+링크(신규 규칙에는 이미 그 형태를 적용했다).
- **actionlint 도입** — 이 리포의 검사기와 **상보적**이다(그쪽은 GitHub 고유 문법, 이쪽은 리포 고유 계약). 미채택 사유는 "이 환경에서 구동할 수 없어 통과를 확인하지 못한 CI 를 커밋하게 된다"였다 — 구동 가능한 환경에서 통과를 먼저 보고 넣어야 한다.
- **`rewrite-exports-src-to-dist.mjs` 의 `main`/`types`** — 지금은 `exports` 만 재작성한다. `main` 이 `./src/` 를 가리키는 소비 패키지가 있으면 게시 후에도 src 를 가리킨다. 소비 패키지의 실제 형태를 아는 쪽에서만 판단 가능해 여기서 결정하지 않았다(현재 동작은 테스트로 고정해 뒀다 — 나중에 바꾸면 그건 의도된 변경이 된다).
